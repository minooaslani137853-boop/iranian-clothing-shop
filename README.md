# فروشگاه آنلاین لباس ایرانی

فروشگاه فارسی، راست‌به‌چپ و با قیمت صحیح به **تومان**؛ فناوری هدف Flask و SQLite با آزمون‌های pytest و Selenium.

## وضعیت مرحله ۵
ثبت‌نام و ورود با هش scrypt، خروج POST با CSRF، لیست و جزئیات محصولات و جستجو و فیلتر ترکیبی دسته، سایز، رنگ و بازه قیمت پیاده‌سازی شده‌اند. صفحات فارسی RTL هستند. سبد خرید، checkout اتمیک، پرداخت Mock، تأیید و تاریخچه سفارش و پنل ادمین نیز آماده‌اند. ظاهر کل سایت مینیمال، فارسی RTL، ریسپانسیو و با فونت محلی وزیرمتن است.

## پیش‌نیازها و نصب
Python 3.12 و Git لازم‌اند. SQLite همراه Python است و سرویس مستقل لازم ندارد.

```bash
git clone https://github.com/minooaslani137853-boop/iranian-clothing-shop.git
cd iranian-clothing-shop
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

در PowerShell فعال‌سازی با `.venv\Scripts\Activate.ps1` است. نسخه وابستگی‌های مستقیم ثابت است؛ requirements فایل قفل وابستگی‌های گذرا نیست.

## اجرا و دیتابیس
```bash
source .venv/bin/activate
flask --app app:create_app upgrade-db
flask --app app:create_app run --debug
```

`init-db` جدول‌های مفقود را می‌سازد و داده موجود را پاک نمی‌کند؛ جایگزین migration برای تغییر schema نیست. داده محلی در `instance/shop.sqlite3` است. SQLite foreign keys برای هر اتصال فعال می‌شود. کلید `SECRET_KEY` از محیط خوانده می‌شود. در توسعه، نبود آن یک کلید تصادفی موقت برای هر اجرای کارخانه می‌سازد و نشست‌ها با راه‌اندازی مجدد منقضی می‌شوند. در تولید کلید پایدار و قوی در محیط تنظیم و `SESSION_COOKIE_SECURE=True` همراه HTTPS اعمال شود. debug فقط برای توسعه است.

`create_app` یک dict تنظیمات یا کلاس تنظیمات می‌پذیرد؛ `TestingConfig` دیتابیس مستقل در حافظه و کلید مخصوص تست دارد. نمونه تغییر مسیر: `create_app({'SQLALCHEMY_DATABASE_URI': 'sqlite:////tmp/shop.sqlite3'})`.

## آزمون و گزارش
```bash
python -m pytest tests/unit tests/integration
python -m pytest tests/system tests/acceptance
python -m pytest --html=docs/test-reports/pytest-report.html --self-contained-html
```

۲۳ تست مدل و کارخانه و ۳۳ تست یکپارچه با Flask test client و SQLite واقعی موجود است. system و acceptance هنوز خالی‌اند. گزارش مرحله ۳ در `docs/test-reports/stage-3.xml` و خلاصه در همان پوشه ثبت شده است؛ HTML به صورت محلی تولید می‌شود.

Selenium به Chrome/Chromium و درایور سازگار نیاز دارد. Selenium Manager در صورت دسترسی شبکه می‌تواند درایور را دریافت کند. برای محیط بدون نمایشگر از `--headless=new` و `--disable-dev-shm-usage` استفاده شود؛ fixture باید مرورگر را با `quit()` ببندد. تست‌ها باید از SQLite موقت و مستقل از داده واقعی استفاده کنند.

## ارتقای دیتابیس و استفاده
`upgrade-db` در دیتابیس تازه همه جدول‌ها را می‌سازد و در دیتابیس مرحله ۲ ستون‌های `category`، `size` و `color` و جدول `user` را بدون حذف داده اضافه می‌کند. اجرای مجدد امن است. پیش از ارتقای داده واقعی نسخه پشتیبان بگیرید؛ این دستور migration عمومی نسخه‌بندی‌شده نیست.

مسیرها: `/register`، `/login`، `/products` و `/products/<id>`؛ `/` به لیست هدایت می‌شود. فرم خروج فقط POST و دارای CSRF است. رمز عبور ۸ تا ۱۲۸ نویسه و ایمیل یکتا و بدون حساسیت به بزرگی حروف است.

دیتابیس تازه عمداً محصول نمونه ندارد. برای افزودن محصول توسعه از shell استفاده کنید:
```bash
flask --app app:create_app shell
```
```python
from app.extensions import db
from app.models import Product
db.session.add(Product(name='مانتو ایرانی', description='پنبه', category='مانتو', size='M', color='آبی', price_toman=350000, stock=3))
db.session.commit()
```
جستجو نام و توضیح را با یکسان‌سازی ی/ک فارسی و عربی بررسی می‌کند؛ فیلترها با AND ترکیب می‌شوند و بازه قیمت شامل دو سر است. هر محصول فعلاً یک SKU با یک دسته، سایز و رنگ است. جستجوی نرمال‌شده فعلاً در حافظه روی نتایج فیلترشده انجام می‌شود و برای کاتالوگ بزرگ باید به جستجوی نمایه‌دار و صفحه‌بندی ارتقا یابد. محدودسازی تلاش ورود، تأیید ایمیل و بازیابی رمز هنوز پیاده‌سازی نشده‌اند؛ پیش از انتشار عمومی لازم است ارزیابی شوند.

## سبد و سفارش مرحله ۴
از صفحه محصول تعداد را انتخاب و به سبد اضافه کنید؛ تغییر تعداد، حذف و جمع کل از `/cart` در دسترس‌اند. موجودی تا ثبت موفق سفارش رزرو نمی‌شود. `/checkout` خلاصه قیمت معتبر سرور را نشان می‌دهد؛ نام گیرنده، تلفن ایران و نشانی لازم‌اند. تغییر قیمت یا سبد تأیید دوباره می‌خواهد. سفارش موفق موجودی را کم و سبد را خالی می‌کند. ارسال مجدد همان فرم سفارش دوم نمی‌سازد.

`/orders` تاریخچه و `/orders/<tracking_code>` تأیید را نشان می‌دهند. برای تاریخچه پایدار پیش از خرید وارد شوید. سفارش مهمان فقط در نشست همان سبد قابل مشاهده است؛ خروج یا از دست رفتن cookie دسترسی را از بین می‌برد. ورود/ثبت‌نام سبد فعلی را حفظ می‌کند ولی سفارش‌های قبلی مهمان را به حساب منتقل نمی‌کند.

پیش از اجرای نسخه جدید `flask --app app:create_app upgrade-db` را اجرا کنید؛ ستون‌های مالک حساب، ارائه‌دهنده و مرجع پرداخت به سفارش‌های قبلی اضافه می‌شوند. سفارش قبلی با مالک NULL مهمان باقی می‌ماند. فایل SQLite و داده شخصی کامیت نمی‌شوند.

### پرداخت
پرداخت فعلی کاملاً آزمایشی و بدون دریافت شماره کارت، CVV، رمز یا تاریخ انقضا است. تنها نام ارائه‌دهنده و مرجع ساختگی در سفارش ذخیره می‌شود. رسید پرداخت Mock با وضعیت `mock_paid` نمایش داده می‌شود و پرداخت بانکی نیست. مبلغ با عدد صحیح تومان محاسبه و از درخواست کاربر خوانده نمی‌شود.

رابط `PaymentGateway` در `app/services/payments.py` با ورودی مبلغ تومان و کلید idempotency و خروجی رسید تأییدشده تعریف شده است. برای تست یا توسعه می‌توان نمونه سازگار را با تنظیم `PAYMENT_GATEWAY` تزریق کرد. خطای `PaymentError` یا مغایرت مبلغ هیچ تغییری در سفارش، موجودی یا سبد ایجاد نمی‌کند.

برای زرین‌پال به آداپتور واقعی و جریان چندمرحله‌ای نیاز است: ایجاد پرداخت pending، تبدیل صریح واحد طبق API انتخاب‌شده، هدایت به صفحه میزبانی‌شده درگاه، callback و verify سمت سرور، بررسی مبلغ و مرجع و نهایی‌سازی idempotent. هرگز نتیجه مرورگر را تأیید پرداخت تلقی نکنید. شبکه بانکی نباید داخل قفل SQLite فعلی فراخوانی شود؛ منطق سرویس پرداخت باید به شروع و نهایی‌سازی جدا تبدیل و رزرو/انقضای موجودی طراحی شود. این اتصال در این مرحله فعال نیست و هیچ کلید بانکی لازم ندارد.

## پنل مدیریت مرحله ۵
پس از نصب و ارتقای schema، یک حساب عادی از `/register` ثبت کنید و فقط از shell سرور به آن نقش بدهید:
```bash
flask --app app:create_app upgrade-db
flask --app app:create_app set-admin --email admin@example.com
# حذف دسترسی مدیر:
flask --app app:create_app set-admin --email admin@example.com --revoke
```
این دستور فقط حساب موجود را تغییر می‌دهد و رمز یا حساب پیش‌فرض نمی‌سازد. نقش از فرم ثبت‌نام، cookie یا پارامتر درخواست پذیرفته نمی‌شود. تمام مسیرهای `/admin/` در سرور بررسی می‌شوند: مهمان به ورود و کاربر عادی به صفحه فارسی 403 هدایت می‌شود. لغو نقش در درخواست بعدی اعمال می‌شود.

پنل شامل نمای کلی، ساخت و ویرایش محصول (قیمت تومان، موجودی، دسته، سایز، رنگ، تصویر و وضعیت نمایش)، حذف محصول بدون وابستگی و مدیریت سفارش است. حذف محصول دارای سبد یا سابقه خرید مسدود است؛ به جای آن غیرفعال کنید. تصویر یک مسیر محلی در `app/static/images/` مانند `images/coat.webp` است؛ بارگذاری فایل یا تصویر از سرویس خارجی در این نسخه وجود ندارد. محصول بدون عکس با جایگزین گرافیکی نمایش داده می‌شود.

وضعیت سفارش به ترتیب `placed` یا `mock_paid` → `processing` → `shipped` → `delivered` تغییر می‌کند. پرش، بازگشت و ارسال مجدد فرم قدیمی رد می‌شوند. این تغییرها اطلاعات پرداخت، مبالغ snapshot و موجودی را دستکاری نمی‌کنند. لغو/بازپرداخت و حذف سفارش برای حفظ سابقه در این مرحله اضافه نشده‌اند.

فونت Vazirmatn نسخه 33.003 از مخزن رسمی rastikerdar/vazirmatn با مجوز OFL در `app/static/fonts/` نگهداری می‌شود؛ بارگذاری فونت به سرویس خارجی وابسته نیست. طراحی شامل ناوبری مشترک، فیلترها، فرم‌های دسترس‌پذیر، وضعیت خالی، پیام‌های فارسی و صفحات 403/404/500 است. صفحه 500 در حالت عادی اطلاعات استثنا را نمایش نمی‌دهد؛ debug در تولید باید خاموش باشد.

اجرای همه آزمون‌ها و گزارش این مرحله:
```bash
python -m pytest --html=docs/test-reports/stage-5.html --self-contained-html --junitxml=docs/test-reports/stage-5.xml
```
گزارش `stage-5-summary.md` و XML نهایی در مخزن ثبت شده‌اند؛ HTML محلی است. آزمون‌های مرورگر این مرحله با Chromium headless و CDP روی دیتابیس آزمایشی مستقل انجام شدند؛ اتصال Selenium هنوز در suite اضافه نشده است.
