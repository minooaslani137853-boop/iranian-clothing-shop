# پوشه — فروشگاه آنلاین لباس ایرانی

فروشگاه فارسی و راست‌به‌چپ با طراحی مینیمال، فونت محلی وزیرمتن، نمایش ریسپانسیو و قیمت‌های صحیح به **تومان**. پیاده‌سازی با Python 3.12، Flask، SQLAlchemy و SQLite است.

## شیوه ساخت پروژه
تمام کدنویسی، مستندسازی، طراحی رابط، نوشتن و اجرای تست‌ها و آماده‌سازی کامیت‌های این پروژه در هفت مرحله توسط عامل هوش مصنوعی انجام شده است؛ در این فرایند کد به صورت دستی نوشته یا ویرایش نشده است. انسان درخواست‌ها و محدوده مراحل را تعیین کرده و ادغام Pull Requestها را انجام داده است. نتایج آزمون از اجرای واقعی به دست آمده‌اند، نه از تولید متن توسط AI.

## قابلیت‌ها
- ثبت‌نام با ایمیل یکتا و رمز هش‌شده scrypt، ورود و خروج با نشست و CSRF.
- لیست و جزئیات محصولات، جستجوی نام/توضیح با نرمال‌سازی ی/ک فارسی و عربی و فیلتر ترکیبی دسته، سایز، رنگ و بازه قیمت.
- سبد مهمان: افزودن، تغییر تعداد، حذف، محاسبه مبلغ معتبر سرور و کنترل موجودی.
- ثبت سفارش اتمیک، snapshot نام و قیمت، جلوگیری از ثبت تکراری و کنترل قیمت و موجودی هنگام checkout.
- پرداخت Mock با مرجع آزمایشی، صفحه تأیید و تاریخچه سفارش‌های حساب و مهمان با کنترل مالکیت.
- پنل ادمین برای محصولات، موجودی و پیگیری وضعیت سفارش‌ها؛ نقش فقط از CLI سرور قابل اعطا است.
- صفحات فارسی 403/404/500، حالت خالی، پیام خطا، برچسب فرم، focus قابل مشاهده و ناوبری با صفحه‌کلید.

## نصب و اجرا، گام‌به‌گام

### ۱. پیش‌نیازها و دریافت پروژه
Python 3.12 و Git لازم‌اند. SQLite همراه Python است و سرویس جدا لازم ندارد.

```bash
git clone https://github.com/minooaslani137853-boop/iranian-clothing-shop.git
cd iranian-clothing-shop
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python -m pip check
```

در PowerShell از `py -3.12 -m venv .venv` و `.venv\Scripts\Activate.ps1` استفاده کنید. نسخه وابستگی‌های مستقیم ثابت است؛ فایل requirements قفل کامل وابستگی‌های گذرا نیست.

### ۲. تنظیم کلید نشست
در Bash برای نشست‌های پایدار توسعه یک کلید تصادفی ایجاد کنید:

```bash
export SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
```

کلید را در Git یا گزارش قرار ندهید. `.env` خودکار بارگذاری نمی‌شود؛ تنظیمات از محیط فرایند خوانده می‌شوند. بدون `SECRET_KEY` کارخانه یک کلید موقت می‌سازد و نشست با اجرای دوباره برنامه منقضی می‌شود. در تولید کلید ثابت و امن را با تنظیمات محیط و HTTPS تأمین کنید.

### ۳. ساخت یا ارتقای دیتابیس
```bash
flask --app app:create_app upgrade-db
```

دیتابیس در `instance/shop.sqlite3` ساخته می‌شود. این دستور روی مخزن تازه همه جدول‌ها را می‌سازد و روی نسخه‌های قبلی ستون‌های مراحل ۳ تا ۵ را بدون حذف داده اضافه می‌کند؛ تکرار آن امن است. پیش از ارتقای داده واقعی پشتیبان بگیرید. `init-db` فقط جدول‌های مفقود را می‌سازد و جایگزین upgrade یا migration نسخه‌بندی‌شده نیست.

### ۴. اجرای توسعه
```bash
flask --app app:create_app run --debug
```

آدرس پیش‌فرض توسعه `http://127.0.0.1:5000` است؛ صفحه اصلی به محصولات هدایت می‌شود. debug و سرور توسعه برای انتشار تولید مناسب نیستند.

### ۵. ساخت ادمین و محصولات
ابتدا با فرم `/register` حساب خود را بسازید. در ترمینال دیگری با همان محیط مجازی و دیتابیس، ایمیل حساب خود را جایگزین نمونه کنید:

```bash
flask --app app:create_app set-admin --email admin@example.com
# لغو نقش:
flask --app app:create_app set-admin --email admin@example.com --revoke
```

هیچ حساب یا رمز ادمین پیش‌فرض وجود ندارد. سپس وارد حساب شوید و `/admin/` را باز کنید. محصولات اولیه عمداً خالی‌اند؛ از پنل محصول، دسته، سایز، رنگ، قیمت تومان و موجودی بسازید. تصویر اختیاری یک فایل محلی مانند `app/static/images/coat.webp` با مقدار `images/coat.webp` در فرم است. بارگذاری فایل یا دریافت تصویر خارجی پیاده‌سازی نشده؛ محصول بدون عکس جایگزین گرافیکی دارد.

تمام مسیرهای ادمین در سرور کنترل می‌شوند. کاربر عادی 403 می‌گیرد و تغییر نقش از فرم ثبت‌نام ممکن نیست. حذف محصول دارای سبد یا سفارش مسدود است؛ برای حفظ سابقه آن را غیرفعال کنید. وضعیت سفارش به ترتیب `placed` یا `mock_paid` → `processing` → `shipped` → `delivered` تغییر می‌کند؛ پرش و بازگشت مجاز نیست.

## معماری و داده
کارخانه `create_app` نمونه‌های مستقل Flask را می‌سازد و dict یا کلاس تنظیمات می‌پذیرد. `app/extensions.py` افزونه SQLAlchemy و نام‌گذاری قیود را نگه می‌دارد. مسیرها در blueprintهای فروشگاه، سفارش و ادمین تفکیک شده‌اند. در نسخه فعلی مسیرهای سفارش orchestration و دسترسی ORM را نیز انجام می‌دهند؛ پوشه repositories هنوز اسکلت است و معماری لایه‌ای کامل نشده است.

مدل‌ها: Product، Cart، CartItem، CustomerOrder، OrderItem و User. ارتباط‌های SQLite در هر اتصال با foreign keys فعال‌اند. قیمت و تعداد قیود عدد صحیح دارند. سبد در سرور است و شناسه آن در نشست امضاشده ذخیره می‌شود. اطلاعات گیرنده در دیتابیس است، نه cookie. checkout با `BEGIN IMMEDIATE` داده را دوباره بررسی و سفارش، اقلام، کاهش موجودی و پاک‌کردن سبد را در یک تراکنش ثبت می‌کند.

تنظیم برنامه سفارشی:
```python
from app import create_app
app = create_app({
    'SQLALCHEMY_DATABASE_URI': 'sqlite:////absolute/path/shop.sqlite3',
    'SESSION_COOKIE_SECURE': True,  # فقط همراه HTTPS
})
```

`TestingConfig` از SQLite حافظه‌ای مستقل و کلید مخصوص تست استفاده می‌کند. برای تنظیمات دلخواه از کارخانه استفاده کنید؛ تمام نام‌های تنظیم Flask به طور خودکار از محیط خوانده نمی‌شوند.

## خرید و پرداخت
سبد از `/cart`، تکمیل خرید از `/checkout` و تاریخچه از `/orders` در دسترس‌اند. موجودی قبل از خرید رزرو نمی‌شود؛ در ثبت نهایی دوباره کنترل می‌شود. تغییر قیمت نیازمند تأیید تازه است. هزینه ارسال و مالیات فعلاً صفر است. برای تاریخچه پایدار پیش از خرید وارد شوید؛ سفارش مهمان فقط با نشست همان سبد قابل مشاهده است. خروج/حذف cookie دسترسی مهمان را از بین می‌برد؛ ورود سبد فعلی را حفظ می‌کند اما سفارش مهمان قبلی را به حساب منتقل نمی‌کند.

هیچ شماره کارت، CVV، رمز یا تاریخ انقضا دریافت یا ذخیره نمی‌شود. پرداخت **صرفاً Mock** است و موفقیت آزمایشی با وضعیت `mock_paid` نمایش داده می‌شود. `PaymentGateway` در `app/services/payments.py` مرز تعویض آداپتور است و از طریق تنظیم `PAYMENT_GATEWAY` تزریق می‌شود.

زرین‌پال فعال نیست. اتصال واقعی نیازمند ایجاد پرداخت pending، هدایت به صفحه میزبانی‌شده درگاه، callback، verify سمت سرور، تطبیق مبلغ و مرجع و نهایی‌سازی idempotent است. تبدیل تومان/ریال باید طبق API انتخاب‌شده صریح باشد. تماس شبکه درگاه نباید داخل قفل SQLite فعلی انجام شود؛ رزرو و انقضای موجودی نیز باید طراحی شوند.

## تست‌ها و گزارش واقعی

### مرورگر
Chrome/Chromium headless نصب‌شده لازم است؛ مسیر اختیاری با `CHROME_BINARY` مشخص می‌شود. Selenium ابتدا امتحان می‌شود و به ChromeDriver سازگار در PATH یا دسترسی Selenium Manager نیاز دارد. فقط اگر startup آن شکست بخورد، تست‌ها به Playwright headless روی Chromium موجود تغییر می‌کنند. در نبود مرورگر می‌توان از نصب رسمی سیستم یا `python -m playwright install chromium` استفاده کرد؛ دریافت فایل‌ها به دسترسی شبکه نیاز دارد.

**علت استفاده از Playwright در این محیط:** cache پیش‌فرض Selenium فقط‌خواندنی بود؛ با cache قابل نوشتن نیز دریافت metadata درایور از `googlechromelabs.github.io` با خطای اتصال tunnel شکست خورد. Chromium با Playwright واقعاً اجرا شد. خطای assertion باعث تعویض backend نمی‌شود؛ اگر هر دو backend اجرا نشوند، تست error می‌شود، نه skip یا pass. گزینه `--no-sandbox` فقط برای مرورگر تست در container استفاده شده است.

### فرمان‌ها
```bash
# واحد و یکپارچه
python -m pytest tests/unit tests/integration
# سیستم و پذیرش روی سرور واقعی
python -m pytest tests/system tests/acceptance -v
# همه تست‌ها و بازتولید گزارش مرحله ۶
python scripts/run_test_reports.py
# اجرای همه تست‌ها و بازتولید گزارش تجمیعی نهایی
python scripts/run_final_report.py
```

تست‌های مرورگر برای هر آزمون سرور HTTP واقعی روی پورت آزاد و SQLite فایل موقت می‌سازند؛ داده‌ها و cookie مستقل‌اند و همه منابع در teardown بسته می‌شوند. مراحل خرید با test client دور زده نمی‌شوند. پرداخت خود MockGateway برنامه اجرا می‌شود و اثر آن در دیتابیس هم بررسی می‌شود.

گزارش مرحله ۷ از XML اجرای تازه، metadata واقعی مرورگر و تاریخچه Git تولید می‌شود؛ کد خروج pytest حفظ می‌شود. نتایج پیشین جایگزین نتیجه جدید نمی‌شوند. [گزارش نهایی MD](docs/final-report.md) و [HTML](docs/final-report.html) شامل شمارش هر نوع تست، خلاصه مراحل، کامیت‌ها و محدودیت‌ها هستند. خروجی کامل در `docs/test-reports/stage-7.html` و `stage-7.xml` ثبت می‌شود.

## محدودیت‌ها
درگاه واقعی، لغو/بازپرداخت، تخفیف، ارسال واقعی، تأیید ایمیل، بازیابی رمز، rate limiting ورود، آپلود تصویر و استقرار تولید پیاده‌سازی نشده‌اند. هر محصول یک SKU با یک سایز و رنگ است. جستجوی نرمال‌شده در حافظه انجام می‌شود و کاتالوگ بزرگ به صفحه‌بندی و نمایه نیاز دارد. SQLite برای بار نوشتن زیاد نیازمند ارزیابی جایگزین است. migration عمومی نسخه‌بندی‌شده و قفل وابستگی‌های گذرا وجود ندارد. قبولی تست‌ها به معنی ممیزی جامع امنیت یا آمادگی قطعی تولید نیست.

فونت وزیرمتن 33.003 همراه مجوز OFL در `app/static/fonts/` است. جزئیات طراحی در [نیازمندی‌ها](docs/requirements.md)، [داستان‌های کاربر](docs/user-stories.md)، [معماری](docs/architecture.md) و [ER](docs/er-diagram.md) آمده است.
